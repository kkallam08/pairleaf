## Product and scope

Pairleaf reveals an existing answer beside its question in the original PDF. It does not generate an answer or judge whether the source answer is correct. Support question papers and textbooks across subjects, with either (1) separate question and answer PDFs or (2) one PDF containing questions and answers. In the one-PDF mode, detect the answer section and offer page-range correction. Match whole numbered questions, including shared subparts and continuation pages. Use chapter, exercise, and section context to distinguish reused numbers.

The selectable-text profile supports clean PDFs, including embedded diagrams. The initial scan profile handles upright English printed exercises with blue/cyan integer labels, explicit exercise headings, and one or two equal-width columns. It renders original PDF crops to preserve formulas and diagrams; OCR text is not a reliable mathematical transcription. General handwriting and arbitrary textbook layouts remain deferred.

## Delivery sequence and gates

1. **Build a checked benchmark and local baseline.** Use the supplied PDF pairs and add non-mathematics material before claiming cross-subject accuracy. Record true question-answer locations and complete reveal regions. Evaluate the current exact-number method, then improve local parsing for plain integers, hierarchical identifiers, changed ordering, page continuations, and section context. **Done when:** the benchmark has verified examples of separate and single-PDF arrangements, ambiguous and missing matches, multi-page answers, and repeated numbers; baseline results are recorded.
2. **Add reliable source matching.** Segment question and answer regions. Rank candidate source regions by structure, numbering, wording, terms, and other relevant evidence. Add an AI-assisted stage for difficult changed-number, order, or wording cases; compare it against the same benchmark. An AI result must point to a real source region. **Done when:** every proposed match has a source location and evidence, while ambiguous cases become suggestions for confirmation or remain unresolved.
3. **Build review and reveal.** Show match evidence before answer content. Keep candidate answers behind explicit preview during review. Let the user confirm or correct a suggestion. Show the whole original answer beside the question, preserve reading position, and support multi-page or multi-region answers. **Done when:** checked examples reveal their complete source answer without neighboring answers and corrections persist for the corresponding documents.
4. **Redesign the interface — completed for both import modes, 2026-11-08.** The compact annotation desk uses a slim tool rail, document tabs, white PDF pages, violet margin markers, sentence-case controls, and concise empty states. File drops, searchable question navigation, review, and the responsive answer pane share the design. Kibo interaction patterns were adapted to vanilla TypeScript. Review-list edge fades follow the shadcn reference. “Answers in this PDF” now enables one-file import and a compact answer-range dialog with optional first/last-page previews. **Verified:** both import modes, reading, reveal, review, range correction, keyboard controls, and mobile layout in Chrome.
5. **Build the local study library — next implementation.** Save the imported PDF or PDF pair with document hashes, the answer-page range, source links, confirmed corrections, and reading position. Provide a library where the user can reopen or remove a saved book. Use local binary-capable storage for PDF bytes and versioned metadata. Handle failed or interrupted saves without displaying incomplete entries. Add export/import for moving or backing up a saved study set. **Done when:** closing and reopening Chrome restores a saved book without selecting files or repeating AI matching; the same answer regions, corrected range, choices, and reading position return; export/import round-trips the study set; removal and storage failures are handled clearly. This step is planned, not implemented in the single-PDF delivery.
6. **Evaluate and deliver the personal/tester version.** Measure wrong automatic assignments, automatic coverage, confirmations per 100 questions, unresolved cases, crop completeness, latency, and cost separately. The initial review-burden target is at most 10 confirmations per 100 questions. Any wrong automatic assignment on the checked release benchmark blocks release; this benchmark cannot prove accuracy on every PDF. Start with free local evaluation. Compare AI on difficult cases with an experimental API-usage ceiling of $10, tracking usage and stopping conservatively before the ceiling. The key is a credential, not prepaid model usage; check existing credits when ready. **Done when:** results, limitations, and regression checks for previously supported PDFs are documented, and a personal/tester build passes them.
7. **Ship a visual-recognition patch — initial Haese subset implemented, moved forward at the user's request.** Bundled Tesseract.js and English data run locally without a helper or API usage. The answer-range dialog enables OCR, a bounded question range, and separate question/answer column counts. Recognition uses printed exercise context, blue margin labels, document-specific digit shapes, and whitespace boundaries. Original answer crops support continuations and same-row answers. All OCR assignments enter review. **Checked gate:** Haese PDF question pages 22–27 and answer pages 485–486 yield 24 proposals for Exercises 1A/1B; inspect all 25 source regions and pass offline recognition, cancellation, restoration, and existing-PDF regressions. **Open coverage:** later chapters, review sets, uneven/mixed columns, other label colors/typefaces, automatic scan answer-section detection, and general handwriting. Evaluate these before broadening claims or allowing automatic OCR assignments.
8. **Prepare public distribution later.** The user deferred API cost and hosted-service choices until after the current product work. When resumed, decide how public users authenticate and pay for AI use, estimate operating cost, and keep secrets in a protected companion or backend rather than extension code. A user's Codex login does not automatically authorize runtime model requests. **Done when:** another user can install and use Pairleaf without the developer's machine or personal key, and the delivery route has been tested.

## Current evidence and limits

- Single-PDF delivery supports one contiguous answer section on separate pages, with questions before that range. Detection recognizes standalone answer headings and stops before a recognized index/glossary/reference section. The user confirms or corrects the proposed PDF page numbers. Source regions retain original page coordinates. Range changes rebuild matches and use a separate correction-cache key. Twenty unit tests and offline Chrome checks pass, including detection, correction, fallback, continuations, repeated chapter/exercise numbering, cancellation, and mobile previews. The broader real-textbook benchmark remains open.
- Haese OCR check: the hidden-text parser still cannot detect the book's answer section. The user selects a small answer range and enables OCR. The checked 24-question subset produces 24 source proposals with no cloud requests; all require confirmation. The complete answer section is PDF pages 485–546, but whole-book recognition and crop completeness are unverified. See RESULTS for the tested ranges, timing, and review burden.

- Steps 1–2, paired-PDF subset: ordinary numbering and exercise context now supplement the dotted profile; question and solution regions carry text for candidate ranking. A local Node helper holds the key and sends bounded excerpts to `gpt-6-luna` only after an explicit AI run. It validates that model output refers to supplied sources, checks current assignments, and sends changed/uncertain matches to review. Candidate retrieval considers at most 12 sources; images, weak OCR, and mixed layouts remain limitations.
- Step 3, paired-PDF subset: source selection, hidden-until-preview answers, confirmation, and corrections keyed by hashes of both PDF files are implemented. Confirmed choices survive reimport; unconfirmed AI suggestions are session-only. Browser checks cover cancellation, changed-file invalidation, and multi-page reveal.
