## Product and scope

Pairleaf reveals an existing answer beside its question in the original PDF. It does not generate an answer or judge whether the source answer is correct. Support question papers and textbooks across subjects, with either (1) separate question and answer PDFs or (2) one PDF containing questions and answers. In the one-PDF mode, detect the answer section and offer page-range correction. Match whole numbered questions, including shared subparts and continuation pages. Use chapter, exercise, and section context to distinguish reused numbers.

The first delivery targets clean selectable-text PDFs, including embedded diagrams. The supplied Haese textbook has page images with imperfect hidden OCR; visual recognition for this book belongs in a later patch. General handwriting support is deferred.

## Delivery sequence and gates

1. **Build a checked benchmark and local baseline.** Use the supplied PDF pairs and add non-mathematics material before claiming cross-subject accuracy. Record true question-answer locations and complete reveal regions. Evaluate the current exact-number method, then improve local parsing for plain integers, hierarchical identifiers, changed ordering, page continuations, and section context. **Done when:** the benchmark has verified examples of separate and single-PDF arrangements, ambiguous and missing matches, multi-page answers, and repeated numbers; baseline results are recorded.
2. **Add reliable source matching.** Segment question and answer regions. Rank candidate source regions by structure, numbering, wording, terms, and other relevant evidence. Add an AI-assisted stage for difficult changed-number, order, or wording cases; compare it against the same benchmark. An AI result must point to a real source region. **Done when:** every proposed match has a source location and evidence, while ambiguous cases become suggestions for confirmation or remain unresolved.
3. **Build review and reveal.** Show match evidence before answer content. Keep candidate answers behind explicit preview during review. Let the user confirm or correct a suggestion. Show the whole original answer beside the question, preserve reading position, and support multi-page or multi-region answers. **Done when:** checked examples reveal their complete source answer without neighboring answers and corrections persist for the corresponding documents.
4. **Redesign the interface — completed for the paired reader, 2026-11-08.** Built the compact annotation desk with a slim tool rail, document tabs, white PDF pages, violet margin markers, sentence-case controls, and concise empty states. Added file drop areas with validation and replacement, keyboard-searchable question navigation, source-location review, and a responsive answer pane. Kibo interaction patterns were adapted to the existing vanilla TypeScript app; no React migration or new component dependencies. Review-list edge fades follow the shadcn reference and never mask PDF content or focused controls. AI setup, explicit source preview, and confirmation now use this design. **Verified:** paired-file import, reading, reveal, review, keyboard focus, and reading-position preservation in Chrome. **Dependency boundary:** “Answers in this PDF” remains disabled until steps 1–2 supply its engine. The full two-mode workflow gate remains open.
5. **Evaluate and deliver the personal/tester version.** Measure wrong automatic assignments, automatic coverage, confirmations per 100 questions, unresolved cases, crop completeness, latency, and cost separately. The initial review-burden target is at most 10 confirmations per 100 questions. Any wrong automatic assignment on the checked release benchmark blocks release; this benchmark cannot prove accuracy on every PDF. Start with free local evaluation. Compare AI on difficult cases with an experimental API-usage ceiling of $10, tracking usage and stopping conservatively before the ceiling. The key is a credential, not prepaid model usage; check existing credits when ready. **Done when:** results, limitations, and regression checks for previously supported PDFs are documented, and a personal/tester build passes them.
6. **Ship a visual-recognition patch.** Use the supplied *Mathematics - Core Topics HL 1 - Haese 2019.pdf* as a required test case. Its answers are mainly final answers, often in two columns; some questions require multiple answer regions. Detect weak OCR and use visual layout evidence where needed. **Done when:** checked textbook examples preserve formulas, graphs, shared context, and complete answer regions without neighboring content.
7. **Prepare public distribution later.** Decide how public users authenticate and pay for AI use, estimate operating cost, and keep secrets in a protected companion or backend rather than extension code. A user's Codex login does not automatically authorize runtime model requests. **Done when:** another user can install and use Pairleaf without the developer's machine or personal key, and the delivery route has been tested.
